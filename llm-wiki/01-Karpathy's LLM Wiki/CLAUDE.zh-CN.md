# LLM Wiki

一个由 Claude Code 维护的个人知识库。
基于 Andrej Karpathy 的 LLM Wiki 模式。

## 目的

这个 Wiki 是一个结构化、相互链接的知识库，用于规划日本之旅。
Claude 负责维护 Wiki。用户负责筛选资料、提出问题并指导分析。

## 文件夹结构

```
raw/          -- 原始资料（不可更改——绝不修改这些文件）
wiki/         -- 由 Claude 维护的 Markdown 页面
wiki/index.md -- 整个 Wiki 的目录
wiki/log.md   -- 仅追加的操作记录
```

## 资料摄取工作流

当用户向 `raw/` 添加新资料并要求你摄取时：

1. 阅读完整的原始资料
2. 在写入任何内容之前，与用户讨论关键要点
3. 在 `wiki/` 中创建一个以原始资料命名的摘要页面
4. 为每个主要观点或实体创建或更新概念页面
5. 添加 Wiki 链接（[[page-name]]），连接相关页面
6. 使用新页面及其一句话说明更新 `wiki/index.md`
7. 向 `wiki/log.md` 追加一条记录，注明日期、资料名称和变更内容

一份资料可能涉及 10～15 个 Wiki 页面，这是正常现象。

## 页面格式

每个 Wiki 页面都应遵循以下结构：

```markdown
# 页面标题

**摘要**：用一到两句话描述本页面。

**来源**：列出本页面引用的 raw 原始资料文件。

**最后更新**：最近一次更新的日期。

---

正文写在这里。使用清晰的标题和简短的段落。

在正文中使用 [[wiki-links]] 链接相关概念。

## 相关页面

- [[related-concept-1]]
- [[related-concept-2]]
```

## 引用规则

- 每项事实性陈述都应注明其来源文件
- 在陈述后使用 `(source: filename.pdf)` 格式标注来源
- 如果两个来源存在分歧，应明确指出矛盾之处
- 如果某项陈述没有来源，应将其标记为需要核实

## 问题回答

当用户提出问题时：

1. 先阅读 `wiki/index.md`，找到相关页面
2. 阅读这些页面并综合整理答案
3. 在回答中引用具体的 Wiki 页面
4. 如果 Wiki 中没有答案，应明确说明
5. 如果答案具有长期价值，可以询问用户是否将其保存为新的 Wiki 页面

优质答案应归档回 Wiki，使知识能够随时间不断积累。

## 检查

当用户要求检查或审查 Wiki 时：

- 检查页面之间是否存在矛盾
- 查找孤立页面（没有其他页面链接到它们）
- 找出页面中提到但尚未拥有独立页面的概念
- 根据较新的资料，标记可能已过时的陈述
- 检查所有页面是否都遵循上述页面格式
- 以编号列表的形式报告发现的问题，并提供修复建议

## 规则

- 绝不修改 `raw/` 文件夹中的任何内容
- 每次变更后都要更新 `wiki/index.md` 和 `wiki/log.md`
- 页面名称使用小写字母和连字符（例如 `machine-learning.md`）
- 使用清晰、直白的语言
- 如果不确定如何对某项内容进行分类，请询问用户
